# 明白金 FinFair 产品需求文档（PRD）

> 版本：V1.0
> 状态：当前课程 MVP 的范围基线
> 依据：`README.md`、`项目制作方案.md` 与当前可运行代码
> 证据口径：文中“已实现”须能由代码、测试或可重复操作证明；商业设想不视为已验证事实。

## 1. 项目背景

金融产品正式文件通常较长，宣传材料又可能突出收益和便利性。消费者购买前需要核对本金、收益、期限、费用、退出条件和风险，但这些信息往往分散在不同页面。

明白金是一款金融产品购买前信息核验 Agent：它将宣传材料与正式说明书逐项对照，把收益、本金、期限、费用和风险翻译成普通用户能理解的说明，并为每个结论提供可追溯证据。

## 2. 目标用户和使用场景

### 2.1 当前首要用户

准备购买或比较理财产品、需要快速理解正式文件的普通金融消费者。

### 2.2 核心场景

用户在购买前上传一份含可复制文字的金融产品 PDF，可选粘贴宣传文案，获得一份带原文和页码的公平说明书。

### 2.3 后续方向

金融机构营销材料一致性初审属于未来 B2B 延伸，不是本期已交付或已验证能力。

## 3. 核心记忆点

**宣传材料怎么说，正式说明书到底怎么写。**

系统不替用户决定买不买，而是提供“结论—通俗解释—原文证据”的核验路径。

## 5. 本期明确不做

- 投资建议、产品推荐或“是否值得购买”的判断；
- 收益预测或保本承诺；
- 正式适当性评估、法律意见或合规认定；
- 真实客户资料处理；
- 扫描件 OCR；
- 多产品横向比较；
- 用户账户、云端历史记录或机构工作台；
- 将未来 B2B 设想描述成当前交付能力。

## 6. 用户流程

```text
阅读用途与隐私提示
→ 选择内置案例或上传文字型 PDF
→ 可选粘贴宣传文案
→ 选择规则模式或自行配置 API
→ 运行分析
→ 查看摘要、风险、宣传核验、Agent 洞察和原文
→ 导出报告
```

## 8. 成功标准

| 编号 | 可验证标准 |
| --- | --- |
| AC-01 | 内置案例能够进入分析流程；未上传文件时不能误生成报告 |
| AC-02 | 内置案例的关键引用能在标记页找到对应文字 |
| AC-03 | 最小缺字段样例不会产生无依据的确定性内容 |
| AC-04 | 冲突宣传样例会产生风险提示 |
| AC-05 | 不存在于指定页面的模型引文不能进入最终洞察 |
| AC-06 | 不保存 API 配置也可以完成规则分析 |
| AC-07 | 仓库文件不包含真实密钥，报告不输出 API Key |
| AC-08 | Markdown、JSON、Word、PDF 下载控件可用且生成内容非空 |
| AC-09 | 页面免责声明明确“不构成投资建议” |
| AC-10 | 长文 Agent 输入发生截断时明确提示未覆盖全文；空白页和 API 失败不丢失规则覆盖数据 |
| AC-11 | 用户能区分两个逻辑阶段和程序门控；虚构引用被拦截；流程按固定条件停止且不夸大模型独立性 |
| AC-12 | 至少12个案例可通过一条命令重复评测；失败案例保留；结果不外推为真实市场准确率 |
| AC-13 | 桌面及375px页面无横向滚动；宣传对照优先；四个下载入口存在；恶意HTML只作为文字渲染 |

所有标准都在 `docs/checklist.md` 中有对应检查项。准确率、用户偏好、付费率等没有充分证据的指标不作为当前成功事实。

## 9. 隐私与金融边界

- 仅使用公开模拟材料或经授权、已脱敏材料；
- 提醒用户不要上传身份证、银行卡、客户档案等敏感信息；
- 启用模型时，PDF 文字和宣传文案会发送给用户选择的第三方模型服务商；
- API Key 只保存在当前 Streamlit 会话状态；
- 输出属于信息辅助，不构成投资建议、收益承诺、法律意见、正式合规审查或适当性评估；
- 重要决定应回到金融机构正式文件并由用户或专业人员复核。

## 10. 项目限制与证据缺口

- 当前仅支持包含可复制文字的 PDF，不支持纯扫描件；
- 规则覆盖有限，大模型也可能遗漏、误解或产生不稳定输出；
- 引用门控能检查引文是否存在，但不能证明模型解释必然正确；
- 当前测试以模拟材料为主，不能外推到所有真实金融产品；
- 现有研究支持问题和设计原则，但不能证明本项目的使用意愿、付费意愿、转化率或机构采购需求；
- 尚无公开部署地址；部署完成前不得写成“已上线”。
